### Focus and layer contract (UX-01, UX-02)

1. Keep one layer record per active floating layer, stable across rerenders. Track its root, invoking element, modal focus boundary, initial target, last valid focus, and relevant parent ownership. Do not reorder on callback identity changes. Handle React StrictMode setup/cleanup, conditional mount, close, and arbitrary unmount order without leaked listeners or locks.
2. Escape closes only the top dismissible active layer and consumes that event. Non-modal popovers participate in dismissal order but never become an independent whole-page focus trap. Retain a current modal boundary while its owned child popover is open; a portalled child must explicitly belong to that boundary. A higher modal suspends the lower modal's containment. Registration of nested children must not depend solely on child-before-parent effect execution.
3. Modal entry captures the invoker before moving focus. Palette starts at its input; existing dialogs keep their intended close/first control; mobile navigation starts at a meaningful navigation/close control. Tab/Shift+Tab wrap through enabled, visible, non-inert tabbables of the active modal and its owned floating children. An empty modal has a focusable root (`tabIndex=-1`). Focus entering obscured content returns to a valid target in the current modal.
4. Make content outside the active modal branch inert while preserving original inert/accessibility attributes. Exclude the active root and owned portals; never inert an ancestor containing the active modal. Restore prior attributes on close/unmount and when ownership changes. Verify background pointer and assistive-technology access, not just keydown cycling. No blanket body `aria-hidden` containing the dialog.
5. Close restores focus to a connected, visible, non-inert invoker when appropriate. Otherwise use the remaining modal's last valid focus or a visible related navigation/task trigger/main region. Route navigation and outside-pointer dismissal must not steal focus from the destination. Lower-layer cleanup must not move focus away from an open higher modal. Capture the original task trigger across inline/overlay mode changes rather than overwriting it with a focused descendant.
6. Desktop navigation is fixed at `>=1024`; detail is inline at `>=1280`. Make CSS and JS use the same shell state/boundary, removing the inclusive CSS `max-width:1024px` conflict. On mobile-to-desktop resize, close the mobile drawer, release only its lock, and choose a visible fallback because the trigger disappears. Overlay-to-inline detail releases modal containment/lock while retaining selection and valid focus. Inline detail never locks or traps the workspace.
7. Match painted order to keyboard order. Existing CSS has mobile navigation 30, popovers 40, detail 45, dialogs 50, palette 55, toast 60; wrappers/stacking contexts can change effective order. Verify the actual combinations. Preserve these bands where correct; if a reproduced nested case disagrees, repair its owning wrapper/portal ordering within this card rather than changing brand/design tokens or adding a second layer manager. Record the chosen fix and a browser regression. Do not introduce a new generic portal primitive without Fragment inspection.
8. Preserve modal labels/descriptions, palette combobox/listbox semantics and IME guards, non-modal filter operation, table J/K/arrow/Enter/Space behavior, and child-control opt-out. Check the module menu's retained menu semantics alongside the account menu; reuse its existing component rather than introducing another menu.

### Read and recovery contract (UX-03–06)

Use explicit request state with successful data separate from pending/error. On retry clear the previous error, start one request using a synchronous in-flight guard, and associate completion/finally with the current request generation. Ignore stale responses after supersession, query change, dismissal, or unmount; a stale finally must not clear a newer pending state. Use existing `apiFetch`/adapter injection seams in tests. No automatic write retries or invented offline/timeout policy.

- **Account:** introduce separate profile loading/error/retry state and reuse `StateRegion`. A rejected `/api/me` settles into Vietnamese recovery; a schema-valid profile renders. Profile retries do not call password/logout endpoints or clear valid form input. Leave `SessionGuard` routing and password/logout behavior intact; the guard also calls `/api/me`, so browser fixtures must first establish its session before failing the page read. Do not move session-context deduplication into this card.
- **Files:** distinguish initial loading, resolved empty, ready, and error for the existing `/api/files` list. Correct its stale source comment about a missing list endpoint. List retry is separate from upload/open. Keep rows on later failure, upload success only after successful PUT, and opening failures beside the operation or through the existing humanized feedback. Guard upload synchronously and track pending opens by file ID, so a second file does not unlock the first. Protect a successful upload from a delayed older list response that would erase it; merge/deduplicate successful local additions made since that list request began. Preserve native file selection, upload payload, object-key policy, and safe open destination.
- **Search:** `GlobalCommandHost` owns current-query remote status/error and retry generation; keep the 250ms debounce and static destinations/actions. `CommandPalette` may add only compatible optional `errorText` and `onRetry` props (or an equally small optional recovery slot). Render error/retry outside the listbox/options, keyboard-reachable within the modal; no action button nested in an option. A failed remote query is distinct from successful zero results even when static groups match. Retry the same trimmed current query; invalidate timers/results when closed, and ensure a late response from a dismissed query cannot repopulate a reopened palette. Clamp/reset active option if result groups change and keep `aria-activedescendant` valid.
- **Notifications:** keep exactly one page polling subscription per generation, separate from the shell's existing subscription. The retry action restarts the page's read subscription, preserving rows; clean up the previous generation. Split mount-only automatic mark-all-read from retry lifecycle so list retries do not repeat that write. A background refresh failure displays recovery alongside current items; announce the transition once rather than on every failed poll. Per-item mark-read has a synchronous ID guard, pending label/disabled state, humanized inline error, and retry by reactivation. Apply `readAt` only after successful acknowledgement; reconcile delayed polling so it cannot revert acknowledged reads. Handle mark-all-read failure without fake read state or unhandled rejection and retain automatic entry behavior. Test read-all/list ordering and newly arriving items; do not indiscriminately mark future notifications read. Keep polling paused when hidden and preserve stream fallback/cleanup.

### Task writes (UX-07)

Move both status and completion request ownership to `QTaskWorkspace`. Use a private ref map/set keyed by task ID as a synchronous gate, plus render state for visible pending feedback. One helper captures `(taskId, nextStatus)` and uses the existing `updateTaskStatus` adapter; completion delegates to it. Status and completion controls for that task disable together. No global lock on unrelated tasks.

Remove the second writer/local saving state from `TaskDetailContent`; its app-internal props may change together with its sole caller. Pass pending into `TaskDetailFooter` and reuse `Button` loading feedback. A response updates its captured task ID, even after the user selects another task; it must not replace the newly selected task. A rejection leaves existing data and selection intact, clears that task's guard, gives recoverable feedback, and permits a new attempt. Confirm success only after the server responds. Unmount suppresses UI effects but does not pretend the server write was cancelled. This is same-client pending protection, not a new server idempotency guarantee.

Outside click/navigation honor the destination. Keep permissions and logout behavior. - Change the existing toast dismiss accessible name to `Đóng thông báo`; keep its existing default close button, timing, remaining-duration pause/resume, stacking and region semantics. Do not implement `closeButton` opt-out semantics here.
- Give unread count neutral existing surface/text tokens, bounded compact geometry and tabular figures. A compact visual count may be capped, but the bell's Vietnamese accessible name retains the true count. Keep the three top actions within the 56px bar with no overlapping touch targets.
- Permit long account values/file names/headings to wrap within `min-width:0` flex/grid tracks. Preserve normal table density (44–48px) and existing local table scroll; document-wide clipping is not a layout fix. Ensure essential content/actions remain reachable at 200% text/browser zoom.
- Keep icon art 16/18px; enlarge mobile hit regions to 44x44px without changing spacing tokens or overlapping adjacent actions. Supply a visible accessible mobile navigation close action using the existing button primitive. In short/tall overlays, use bounded scrollable content and reachable close/footer regions; add no native safe-area/keyboard APIs. Mobile focused inputs must avoid forced zoom, scoped to relevant narrow layouts while retaining desktop typography.
- Preserve existing color/font/spacing/radius tokens, neutral selection, floating-only shadows and one primary amber CTA. Reduced motion must leave static loading feedback understandable; verify buttons, skeletons, drawers and palette with computed styles.
